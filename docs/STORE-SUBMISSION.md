# Chrome 웹 스토어 제출 준비

아래는 초안입니다. 실제 학교·담당자·HTTPS 개인정보처리방침 URL·지원 연락처를 채우고 학교/교육청의 승인을 받아 제출합니다. 게시나 심사 완료를 뜻하지 않습니다.

## 목록 문구 초안

이름: 학교 배포 진단 시험

짧은 설명: 배포 시험 중이며 검색·방문기록은 수집하지 않음

상세 설명: 학교 관리 계정의 확장 배포, 실행, 기기 식별 API 및 비대화형 서버 인증 가능성을 확인하는 1단계 진단 시험입니다. 설치·시작·주기 알람에서 진단하며, 아이콘을 클릭하면 계정·기기·서버 연결 상태를 확인할 수 있습니다. 자동 창이나 로그인·승인창을 띄우지 않습니다. 방문 URL, 검색어, 페이지 내용, 방문기록을 읽거나 보내지 않습니다. 시험이 활성화되고 학교 계정·토큰 검증 조건을 통과한 경우에만 제한된 상태 정보를 승인된 학교 서버에 전달합니다. 실제 정책 설치·기기 등록·무조작 인증의 가능성은 조직 설정에 따라 별도 확인이 필요합니다.

단일 목적 설명: 학교 배포·인증·기기 정보 API의 작동 여부를 진단하는 시험.

## 권한·개인정보 항목 작성 근거

- identity: Google 비대화형 OAuth 인증. identity.email: 프로필 이메일·ID의 로컬 진단 및 서버 인증 계정과 대조.
- enterprise.deviceAttributes: 학교 관리자 승인 하에 Directory 기기 ID 진단. 일련번호·위치 정보는 읽지 않음.
- storage: 중앙 정책과 로컬 진단 상태·재시도 시각. alarms: 기본 5분 진단, 지연·실패 시 재시도 제한.
- host permission: 실제 승인된 시험 서버 **한 HTTPS 원점**에 상태 전송. 모든 사이트 접근 없음.
- 원격 코드: 없음. 패키지 안의 JavaScript만 실행. Google OAuth 및 서버 데이터 응답은 원격 코드 실행이 아님.
- 사용자 데이터 없음으로 답하지 마세요. 인증된 학교 이메일, 기기 Directory ID(있을 때), 플랫폼·설치 유형·버전·연결 상태가 처리됩니다. 대시보드의 현재 데이터 분류 명칭에 맞게 식별정보/진단정보를 정확히 선언합니다. 웹 방문 이력은 수집하지 않습니다.
- 서비스 계정 비밀키·공유 인증 우회 키·교사 비밀번호는 확장에 없습니다.

## 개인정보처리방침 초안 내용

운영 주체: [실제 학교/교육청 담당 조직]

목적: 학교 확장 배포와 기기 API·인증·연결 진단 시험. 시험 학생 2~3명에게만 정책 적용.

로컬 처리: 기본 Chrome 프로필 이메일·Google ID, Directory 기기 ID(제공될 때), 설치 유형·플랫폼, 진단 상태, 상세 오류, 마지막 실행/연결 시각과 재시도 예정 시각. 접근 토큰은 자체 저장소에 저장하지 않으며 Chrome identity 캐시는 Chrome이 관리합니다.

서버 처리: Google에서 검증한 학교 이메일, 학교 식별값, Directory 기기 ID 또는 null, 설치 유형·플랫폼·확장 버전, 실행 원인·전송 간격, 이전 실패 유무, 서버 수신 시각. URL·검색어·페이지 내용·방문 이력은 제외됩니다. 상세 오류 문자열은 서버에 보내지 않습니다.

접근: 서버 전용 인증을 통과한 교사만 상태 조회. 인증 전 상태 POST 없음. Google 토큰 검증 과정에서는 Google HTTPS 서비스에 토큰을 전달합니다. 운영 서버 주소: [실제 HTTPS 주소].

보관: 기본 14일. 학교 승인 설정에 맞춰 실제 보관 기간을 명시합니다. 기기/계정별 최신 행을 갱신하고 만료 데이터를 정리합니다. 복구·백업·문의 및 삭제 방법: [승인된 실제 절차와 연락처].

학생 안내: 확장 아이콘에서 시험 목적·수집 제외·상태 확인 가능. 설치 사실이나 수집 권한을 숨기지 않습니다.

이 초안에는 법적 운영 승인이 포함되어 있지 않습니다. 실제 운영 주체가 검토한 최종 정책을 HTTPS 페이지에 게시하고 그 URL을 제출합니다.

## 제출 전 목록

1. 조직 승인된 게시 계정, 개발자 등록 및 보안 요구·연락처를 확인합니다.
2. 초안 ZIP 업로드로 Item ID와 공개 키 확보. 아직 설치 가능한 게시 완료 상태가 아닙니다.
3. 해당 Item ID에 연결한 OAuth client ID·실제 서버 한 원점·public key로 재빌드하고 ZIP 업데이트.
4. 실제 아이콘(패키지에 포함), 진단 화면을 직접 캡처한 스크린샷, 목록 설명, 지원 연락처·정책 URL을 준비합니다. 스크린샷에는 실제 학생 이메일·기기 ID를 노출하지 않습니다. 스토어 대시보드가 요구하는 크기/이미지 종류를 확인합니다. 아직 실제 브라우저 스크린샷은 제공되지 않았습니다.
5. Privacy practices와 권한 사용 근거를 입력합니다. 조직 비공개 게시 권한이 활성화되었는지 확인합니다. 비공개/테스터 공개 범위와 관리자 강제 설치 그룹은 별개입니다.
6. 심사 제출 → 승인 → 게시 가능한 상태를 확인합니다. 비공개도 심사를 생략한다고 가정하지 않습니다.
7. 실제 게시 Item ID를 복사하여 시험 그룹의 ID 추가 팝업에 입력합니다.
