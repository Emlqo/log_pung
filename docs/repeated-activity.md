# 반복 활동 묶기

같은 이메일의 같은 URL·검색어가 연속해서 발생하면 첫 기록부터 최대 5분 동안 한 줄로 표시합니다. 최초·마지막 발생 시각과 횟수를 보여줍니다. 다른 사이트나 검색어가 끼거나, 한국 날짜 또는 수집 ON 세션이 바뀌면 새 묶음입니다. 다른 학생의 활동은 영향을 주지 않습니다.

기존 기록은 조회 시에만 묶습니다. 기존 원본을 병합하거나 삭제하는 마이그레이션은 없습니다. 새 기록은 URL 등을 한 번 저장하고 발생 시각 목록을 보관합니다. 재전송 중복 검사를 위해 이벤트 키·내용의 해시와 발생 시각을 별도 저장합니다. 따라서 화면의 줄 수 감소율이 실제 DB 용량 절감률과 같지는 않습니다. 확장 프로그램 업데이트는 필요하지 않습니다.

늦게 도착한 다른 사이트 기록이 저장된 묶음 중간에 있으면 묶음을 분리합니다. 늦게 도착한 같은 사이트 기록은 별도 행으로 저장될 수 있으며 조회 시 가능한 범위에서 합칩니다. 저장 묶음당 최대 1,000회로 제한합니다. 검색 필터를 적용하기 전에 묶으므로 A→B→A에서 B가 검색 결과에 없어도 A를 하나로 합치지 않습니다.

7일 보관은 개별 발생 시각 기준으로 유지합니다. 묶음 중 일부만 조회 기간에 속하면 해당 횟수만 표시하고, 보관 기한이 지난 발생 시각과 재전송 검사 정보도 정리합니다. 원본 개별 이벤트 ID 목록은 조회 API에 노출하지 않습니다.

조회는 사용자가 조회 버튼을 눌렀을 때 실행합니다. 날짜·학생 범위의 기록을 스트리밍으로 읽어 묶고 100줄씩 반환합니다. 필터 뒤의 정확한 묶음 개수를 계산하기 위해 해당 범위를 읽으므로, 장기간 전체 학생 조회는 좁은 기간·학생 조회보다 비용이 큽니다. 운영 PostgreSQL의 실제 부하와 물리 용량 절감률은 별도 관찰이 필요합니다.

검증: 반복 저장, 재시작 후 재전송, 변조된 재전송 거절 및 트랜잭션 롤백, 학생/검색/수집 세션 경계, 5분·한국 자정 경계, 지연 도착에 따른 분리, 기간 일부 조회와 보관 기한 정리, 기존 행 보존, 페이지·정렬을 자동 테스트합니다.
